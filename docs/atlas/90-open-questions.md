# 90 — Open Questions

[← Index](00-index.md)

| ID | Question | Raised on |
|---|---|---|
| OPEN-5 | Which models write the document, make the decisions, and make the embeddings? The agentic loop is now on plate 60: two LangGraph agents, one that ratifies tags and one that writes the report. The earlier recommendation stands as a starting point: Claude for writing and decisions, and a small open embedding model inside the container so reviewers need only one key. | [40](40-backend.md) |
| OPEN-10 | Trends need history that on-demand tagging doesn't create. Extrapolation (plate 50) needs every earlier week tagged, but tagging runs only over the period someone requests. If only last week is ever requested, the earlier seven weeks have no tags and there is nothing to extrapolate. The recommendation: requesting a report for a period first tags, oldest first, every untagged week in the eight before it, then the period itself. On the committed snapshot that has already been done (OPEN-13), so it costs nothing at demo time. | [21](20-data-model/21-topics.md), [50](50-prediction.md) |
| OPEN-11 | The backtest can cheat without anyone noticing. If tags were minted while looking at the held-back week, the prediction for that week is built on tags that already know what happened. The recommendation: tagging always moves forward in time, one week at a time, and the backtest uses only the tags and centroids as they stood at the end of the week before the held-back one. The cluster_decisions log already records when each tag was minted, so this is a filter, not new machinery. | [50](50-prediction.md) |
| OPEN-12 | Retrieval statistics have nowhere to live. The brief asks for counts of which embeddings are retrieved most, and plate 60 says every search and lookup hit is counted, but no table holds the counts. The recommendation: a retrieval_events table, one row per passage returned, with the run, the agent, the tool and the time, so the statistics screen can show most-retrieved overall, per run, and for the report agent separately from the tagging agent (whose searches would otherwise swamp the numbers). | [21](20-data-model/21-topics.md), [60](60-agents.md) |
| OPEN-13 | What exactly is in the committed snapshot? Raw posts alone would mean the reviewer's first boot has to embed eight weeks of posts and run the tagging agent over all of them, which takes time and costs model calls before anything is on screen, and gives different tags each time. The recommendation: commit the raw posts plus the embeddings, the tags, the cluster decisions, and one finished comparison run, so the app opens fully populated with no key at all; a fresh tagging or report run is then the live part of the demo and needs the reviewer's key. | [40](40-backend.md) |
| OPEN-14 | Handling too much data is not planned yet, though the brief asks for it. r/sailing is roughly a hundred posts and a few thousand comments a week, so eight weeks is tens of thousands of items. The recommendation: drop deleted, removed and bot comments (AutoModerator); drop comments under a minimum length that carry no content ("this", "+1"); cap comments per thread, keeping the highest-scoring and the earliest; cut long posts into overlapping passages; and record each limit with its reason on an ingestion plate. | [40](40-backend.md) |
| OPEN-15 | The comparison measurements aren't designed. CLAUDE.md §7 lists them (claims that trace to a real post versus claims that don't, topics covered and missed, specificity, time and tokens) and plate 60 only says they're code plus at most one fixed judging prompt. The recommendation: a comparison plate that defines each measurement, how it's computed, and the comparison_runs table that stores both outputs, the prompts, the tool calls and the scores. | [60](60-agents.md) |
| OPEN-16 | The document's own shape isn't specified: its sections, how long it is, whether it quotes posts, whether it includes charts. The brief allows any format. The recommendation: a web page with a fixed outline (the week in one paragraph; the main topics, each with what was said, notable threads and short quotes linked to their posts; then next week's prediction, each item with its trend chart and evidence), produced as structured output so the page can render the charts and links, with a markdown export. | [30](30-frontend.md), [60](60-agents.md) |
| OPEN-17 | The screens are short two the design now needs: a topics screen showing each tag's engagement over time (the graph Brian asked to be easy to draw), and a way to request a report or tagging run for a period and watch its progress. The recommendation: add both to plate 30 alongside the document, comparison, embedding map and retrieval statistics screens. | [30](30-frontend.md) |
| OPEN-18 | How the whole thing boots is not on any plate: six services (frontend, API, Postgres, Redis, Celery worker, Celery Beat), the snapshot load, the database setup, and which key the reviewer supplies. The README promises one command. The recommendation: an environment plate covering the compose file, a one-time setup step that runs automatically on first start (create tables, load the snapshot), and .env.example with the single key, depending on OPEN-5. | [01](01-system-map.md) |

## Resolved

| ID | Decision | Date |
|---|---|---|
| OPEN-1 | The frontend's API client is generated from an OpenAPI description the backend publishes (typed TanStack Query hooks, for example with orval). The backend choice must support publishing one. | 2026-10-18 |
| OPEN-2 | The embedding map is drawn with Apache ECharts. | 2026-10-18 |
| OPEN-4 | Similarity search is done in Postgres with the pgvector extension, for both jobs: comparing clusters with topic tags, and retrieving passages for the document. | 2026-10-18 |
| OPEN-6 | Posts are fetched daily. Clustering is not on a fixed schedule: it runs on demand, over whatever time period is requested. | 2026-10-18 |
| OPEN-7 | The committed snapshot holds eight weeks of history: seven to fit trends, one held back for the backtest. | 2026-10-18 |
| OPEN-3 | The community is r/sailing on Reddit, fetched from Reddit through the Arctic Shift archive (OPEN-8). Trawler Forum was ruled out because it blocks automated access and bans AI crawlers in its robots.txt; r/trawlers was ruled out because it isn't busy enough for eight weeks of clusters and trends. | 2026-10-18 |
| OPEN-8 | r/sailing's posts and comments are fetched from Arctic Shift (arctic-shift.photon-reddit.com), a free research archive of Reddit that needs no key, for both the eight-week history and the daily fetch. Reddit's own API was ruled out for now because creating an app requires approval under its Responsible Builder Policy. | 2026-10-18 |
| OPEN-9 | The committed snapshot keeps authors' real Reddit usernames; no pseudonyms. | 2026-10-18 |
